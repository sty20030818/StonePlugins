# 公开决策说明

当回复包含实质工程决定时读取本文件。目标是帮助用户判断和学习“哪些事实让哪些方法产生了什么决定”，不是输出隐藏思维、规则签到或方法论教材。

## 固定语义

- 完整常驻工程执行契约共同形成方案；公开说明只展开它产生的可观察决定。
- 以**决定**组织内容，一个决定可以由多个方法共同形成；不要按方法名制造多个虚假决定。
- 每项说明必须形成“事实与约束 → 方法的具体作用 → 决定 → 影响与取舍”的闭环。
- 方法论是总称；具体标注为工程原则、架构方法、改造策略或验证方法。没有准确名称时写“工程判断”或“用户明确约束”。
- 只读取、检查、与结果相容或事后贴名不算采用；不要机械列出全部常驻名称。
- 影响只写当前场景真实存在的收益、代价和剩余风险，不虚构替代方案或缺点。
- 验证命令和结果仍由正常验证部分持有，不在这里复制日志或把计划写成已完成。

## 位置

- **方案**：推荐或结论 → 决策说明 → 真实备选与待确认项。
- **实施交付**：结果 → 决策说明 → 验证证据与未覆盖边界。
- **诊断或审查**：根因或发现 → 决策说明 → 支撑证据和后续建议。

说明紧跟它解释的决定，不统一堆到回复末尾。更高优先级的长度、格式或用户明确要求优先；需要压缩时保留因果，不保留方法名装饰。

## 通用开头

所有公开决策说明都先使用同一个标题和简短说明：

```md
## 🧭 为什么这么做（石头鱼的工程规则）

完整常驻契约共同形成方案；这里只列真正改变结果的决定。
```

标题不得放入引用。Emoji 只用于定位，删除后文字仍须完整可懂。

## 一至两个决定

在通用开头后，每个决定使用一个三级标题，引用只承载事实、方法作用和影响。方法标签与影响与取舍标签都加粗；方法标签结束的 `**` 后必须保留一个 ASCII 空格，避免强调标记与正文黏连。影响与取舍另起一段。只有一个决定时删除第二组，不保留占位符：

```md
### {决定一}

> **{方法（分类）}** 依据{事实与约束}，使方案{方法产生的具体作用}。
>
> **影响与取舍**：{当前收益、代价或剩余风险}。

### {决定二}

> **{方法（分类）}** 依据{事实与约束}，使方案{方法产生的具体作用}。
>
> **影响与取舍**：{当前收益、代价或剩余风险}。
```

决定标题不得放入引用；引用内的空行只负责让影响与取舍换行，加粗标签负责视觉区分。

## 三个以上决定

三个以上决定时，在通用开头后使用紧凑表格：

```md
| 关键决定 | 方法论如何产生决定 | 结果 | 影响与取舍 |
| --- | --- | --- | --- |
| **{决定}** | {方法（分类）}：{事实及具体作用} | {形成的方案或改动} | {收益、代价、风险} |
```

高风险、需要确认或存在真实竞争的决定可以在表格后展开。
