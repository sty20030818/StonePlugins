# StonePlugins：Codex 优先重构计划

日期：2026-09-14，发布授权更新于 2026-09-15。完整插件已在 `0.5.1` 发布，证据由 [v0.5.1 评测](../evals/v0.5.1.md)持有。此前精简稿丢失了部分方法的独有语义，本轮按用户确认恢复完整常驻原则与按需方法，保留一级路由、同包分发和核心注入，不指定模型。内容恢复完成后，用户授权发布新版本并更新安装，本轮按 `0.5.2` 执行提交、推送、tag、CI、GitHub Release 和远端安装更新；真实宿主接收与行为仍单独验收。

## 基线与目标

当前内容精简以已发布 `0.5.1` 为基线，发布版本为 `0.5.2`，证据见 [v0.5.2 评测](../evals/v0.5.2.md)。`0.5.0` 的两步安装、首次完整插件迁移及当时的 60 次评测延期，分别保留在 [ADR-0003](../adr/0003-independent-skill-and-loader-hooks.md)、[候选开发验证](../evals/codex-first-bundled-development.md)和版本评测中，不再作为待执行步骤。

目标：完整常驻原则共同形成每项工程决定，相关方法可以同时采用；条件决定具体结构和流程，不把整套原则关闭。按当前问题直接找到三份细则，保留方法独有的动作、适用边界和退出条件，合并重复表达；不强制经过方法选择器或公开说明模板。先保证语义完整，再衡量长度、读取和 token 成本。方向见 [ADR-0004](../adr/0004-codex-first-bundled-engineering.md)，来源和前次评测限制见[指令精简研究](../research/2026-09-14-astra-instruction-simplification.md)。

沿用 TypeScript、npm、提交生成 JavaScript 的构建流程和 Node `22.18.0` / `24` CI，不新增依赖、工作流框架、模型选择器或运行时模式开关。

## 不变的分发与加载契约

- 插件 `stoneplugins@stonefish` 同包提供 `engineering` Skill 与三个 Hooks，唯一 Skill 树为 `plugins/stoneplugins/skills/engineering/`。Codex 原生入口为 `$stoneplugins:engineering`；其他 CLI 只独立安装同源 `$engineering`，不增加根目录镜像或兼容副本。
- `SessionStart` 的 startup、resume、clear、compact，以及 `SubagentStart`，从实际运行脚本所在的插件缓存读取核心，移除 frontmatter 后完整送达。输出提供当前 Skill 和资源目录，核心只适用于工程任务，不展开全部细则。
- 同一有效上下文已完整收到核心时，不为徽标或计数重复读取。核心未完整收到时走正常 Skill 入口；`UserPromptSubmit` 仅发送不超过 300 UTF-8 bytes 的提醒，不读取 prompt/transcript 或按关键词路由。
- 生命周期上下文上限仍为 8,000 UTF-8 bytes。超限、缺失、不可读、损坏或空核心时，输出脱敏错误与工程暂停要求，不截断为成功、不联网安装、不使用旧缓存或硬编码兜底。字节预算不等于 token 或宿主完整性证明。
- Hook 不写日志、不保存状态、不修改信任哈希。宿主审批、沙箱和真实执行证据与文字暂停要求分别验证。

## 验证与停止条件

先检查工作树与暂存区，保持用户分界。根级入口为 `npm run check`、`git diff --check`；新文件保持未暂存，不为运行发布校验擅自改变 Git 状态。只有另行授权发布时才进入 `npm run validate:release`、版本同步与远端写入流程。

确定性检查覆盖：

- 四类 SessionStart 与 SubagentStart 的正文逐字等于候选 Skill 去 frontmatter 的结果，逐轮提醒满足短预算。
- 非法输入、未知事件和原型属性不会泄漏 prompt/transcript 中的内容。
- 完整包复制到含空格的缓存目录后，不依赖源码 checkout 或外置 Skill 即可运行，三个引用文件可达且不能逃逸插件根。
- 缺失、不可读、损坏、空核心和超预算返回单一安全 JSON；重建没有生成物漂移。

再逐项核对[语义映射](../methodologies.md#语义保留与改写映射)，确认独有动作仍在核心或三份细则中，检查主动采用条件是否被误写成“发生问题后才采用”。这是静态语义审查，不等同模型行为通过，也不要求把方法名或模板短语写入校验器。

然后按[活动评测规范](../evals/behavior-cases.md)选择少量针对性正反案例；四个代表案例、旧新各一次可作为 8 回合探索，不能为了固定数量漏掉本次变化。优先覆盖单实现隔离与假想扩展、明确目标与未知遗留行为、主动架构检查与无价值门禁，再按相关风险复用非法输入、403、Git 分界和修改范围案例。实现案例提供可运行样例。沿用当时默认模型，记录实际模型与推理强度，完整保留其他 Skill 配置；两侧只改变被测规则，同批配置不一致时不直接比较。

内容修改也要核对候选正文完整送达及直接细则可达；涉及 Hook、包装或资源路径变化时，补齐受影响的真实生命周期。脚本输出、宿主接收、模型行为、UI 徽标和调用次数分别记录。小样本不证明跨模型可靠性、稳定行为等价或固定 token 收益。

出现核心遗漏、资源失联、覆盖用户修改、权限或数据错误、伪造验证等关键失败时先修复；普通分歧、漏读或疑似成本回归只扩测相关案例。必要检查通过且没有新变化、失败或未解决风险后停止，不为凑次数重复运行。

## 安装与发布边界

用户已选择 GitHub 安装来源，本轮不切回桌面源码，不直接覆盖已发布 `0.5.1` 缓存。发布后将固定来源更新到 `v0.5.2`，用原生插件安装命令取得新的版本化缓存；仓库文件修改本身不构成更新安装。

本轮已获新版本授权，同步根 package、lock、插件 manifest、CHANGELOG、固定 ref 示例与版本评测；核对目标来源和已有配置，再执行提交、推送、tag、CI、GitHub Release 和远端更新。CI 只验证，不自动创建 Release。配置或缓存变化后通过新任务验收，不能把旧任务已有上下文当作更新成功。

升级继续停用旧插件后再启用新插件，不并行两份注入；仅禁用 Codex 的旧精确 Skill 入口，保留其他 CLI 使用的共享目录及链接。不自动恢复信任、不覆盖无关配置，不用 stash/reset 处理用户修改。需要回退时恢复已记录的精确版本与本次配置变更，不重写用户代码历史。
