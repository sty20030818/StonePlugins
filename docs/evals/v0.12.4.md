# v0.12.4 版本验证

## 受检范围

工程小结有实际后续时写下一步和接手人。没有待办且有值得考虑的延伸时，可以写一条可选想法。两种结尾最多出现一组，整件事确实收尾时直接结束。按 [TIMING-1](behavior-cases.md#timing-1-工程回复与接续) 验证小结格式。

## 候选检查

2026-11-27，`npm run check` 的 57 项测试全部通过。在四个独立的临时 Codex CLI 0.171.0 会话中使用本机默认模型 GPT-6.2 Sol ultra，注入候选 Hook 直接输出的完整核心和逐轮提醒，隔离其他规则来源。当前源码路径下，核心 7,677 字节，提醒 298 字节。

| 用例 | 通过条件与结果 |
| --- | --- |
| 实际待办与想法并存 | 只列真实下一步，标题有复核动作，同组写明接手人。 |
| 只有可选延伸 | 只列一条可选想法，写出诊断页集中展示事务 ID 的具体方向。 |
| 已全部收尾 | 只汇报核对成果，省略两种接续。 |
| 待授权 | 单列下一步，在同组写清决定人、执行者、推荐与两个时段的影响，只留一个独立引用问题。 |

四例均通过，出现的标题均有要点，未附提示词。初次样例中曾有授权角色只出现在成果组或引用中，最终正文明确由下一步组交代决定人与执行者。本批验证候选内容的回复行为，独立于宿主生命周期的真实送达。
