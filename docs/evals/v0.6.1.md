## 安装与宿主行为

桌面内置 Codex CLI 0.166.0-alpha.6 已将 marketplace 固定到 v0.6.1 并安装启用目标插件。29 份缓存文件逐字匹配发布 tag；工程核心与 Hook 保持原样。三个 Hook 在新路径初始为 modified，沿用户既有授权通过正式 config/batchWrite 接口重新信任，独立回读均为 trusted。其他配置及个人 AGENTS 未变。

同版本 app-server 新进程以六个原始 ephemeral turn 验证，实际模型 gpt-6.1-sol、推理强度 ultra，沿用用户配置。三个自然语言请求不含技能名或路径，均实际读取匹配的 0.6.1 SKILL；三次原生选择使用结构化 skill 输入，注入全文逐字匹配缓存。六例均读取共同约定与相应 SOP，所有 turn completed/error null，54 项机械事实检查及独立语义审阅通过。

| 入口 | 自然语言场景 | 新上下文的原生接续 |
| --- | --- | --- |
| task | 只读分析，不测试不写文件 | 交付 trim、复验 4/4，先保存读回证据再任务 done；阶段保持 doing |
| verify | 两项实际失败，保留实现/测试/标准，任务 doing | 核对当前对象与标准匹配，复用 4/4，不重跑；补任务条件原文和批次 |
| review | 识别占位验收，拒绝收尾且无写入 | 逐项判断后先记录读回，再阶段 done、原地归档与历史入口 |

首批 task 的 .test.js 快照被 Node 自动扫描，实际产生 8 次执行（2 过 6 败），并非 8 个独立场景。执行者保留原始失败、更正为 .txt 原文副本，之后 4/4 通过；verify/review 均确认该更正。该采集偏差已纠正，不隐去历史失败，也不把失败的验收对象称为交付通过。

三个目标 Hook 在同一新进程中共 16 次 completed，SessionStart/SubagentStart 上下文包含与安装文件一致的完整工程核心，逐轮提醒为 288 UTF-8 bytes。完成后通过正式接口精确移除两个临时项目信任；最终相对更新前仅变化目标 ref 与三个获准 Hook 信任摘要，其他配置及个人 AGENTS 未变，29 份缓存的文件集合/字节仍匹配 tag。
