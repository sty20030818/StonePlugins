## 核心生命周期

使用 Codex 原生 app-server 协议和既有已信任 Hook，不手工伪造宿主事件，不改动当前用户对话。临时会话使用只读沙箱；只有冷恢复需要持久化一条验收记录，完成后已归档，可恢复。

## 失败与证据边界

- 最早的旧 `0.5.0` 本地候选在压缩后 Hook 已完成，但模型响应超时；不计为通过。最终 `0.5.1` 独立会话的实际压缩和接收通过，旧超时原因未归因于插件或模型服务。
- 无持久记录的 ephemeral 会话返回 `no rollout found`，不能用于恢复测试；同进程重新订阅也只证明历史仍可读，没有重新触发 Hook，因此都不算冷恢复通过。
- 已归档记录拒绝恢复；只将本次精确验收记录取消归档，再由新进程冷恢复，捕获真正的 `SessionStart`，完成后再次归档。
- 系统 Python 缺少 PyYAML；使用已有 `skill-validator` 环境重新运行官方检查并通过，未新增项目或全局依赖。
- 这是核心送达与安装验收，不等于已证明长期工程行为、所有客户端 UI 或跨平台宿主表现。Windows 实机、其他 CLI 原生 Hook 与 60 次行为/token 对照未执行。
