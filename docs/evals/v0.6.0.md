## 来源与验收范围

SOP/模板来自 [StoneDocs 提交](https://github.com/sty20030818/StoneDocs/commit/67c3a415f95b92e0c802165df0c326099409e411)，逐字匹配 source.json 的文件摘要。发布前的五个隔离试跑见[开发记录](document-workflow-development.md)；那些结果不能代替本版安装或宿主触发验证。

本次依次核对本地根检查、发布检查、远端 CI/Release、实际安装缓存和新宿主行为。以下记录本轮实际结果，后续样例另行追加，不改写旧失败。

## 本地与发布

本地 npm run check 已通过类型、构建、资源校验及 17 项测试（7 项工作流、10 项原工程 Hook）。CI 已改为 npm test，覆盖同一完整测试集合。来源原文已与 StoneDocs 指定提交逐字核对。发布提交为 `433865e4559f28923684054544cea20127d7f51c`，main 和 tag 已推送。[main CI](https://github.com/sty20030818/StonePlugins/actions/runs/41975733027)与 [tag CI](https://github.com/sty20030818/StonePlugins/actions/runs/41975735519)在 Node 22.18.0、24 均通过。[Release](https://github.com/sty20030818/StonePlugins/releases/tag/v0.6.0)已正式创建并回读，非草稿、非预发布。

## 实际安装与宿主行为

通过桌面内置 Codex CLI 0.166.0-alpha.6 将 stonefish 固定来源更新为 v0.6.0，指定插件已安装且启用；20 份缓存文件逐字匹配发布 tag。其他插件启用状态和全局 AGENTS 保持原样。

用同版本 app-server 的全新 ephemeral 上下文执行六个原始案例，实际模型 gpt-6.1-sol、推理强度 ultra，沿用用户配置。原生显式组使用结构化 skill 输入，宿主注入的三份正文逐字匹配安装文件；自然语言组不写技能名或路径，均自主读取对应 0.6.0 技能。

| 入口 | 自然语言场景 | 原生显式接续 |
| --- | --- | --- |
| task | 只读分析任务，文件未改 | 保留失败复现，修复 trim，4/4 测试通过，证据读回后 done；不归档阶段 |
| verify | 实际检查失败，保留实现、标准及 doing | 新上下文核对对象与已有通过证据，复用测试结果并追加核对，没有再改实现或重跑测试 |
| review | 识别占位证据，暂不收尾且不写文件 | 新上下文先记录判断，再完成阶段与原地归档，更新导航 |

因此本轮观察支持三个入口的显式调用、自然语言选择，以及依靠文档交接的 task → verify → review 配合；六个原始 turn 均 completed 且 error 为 null。原生 review 已收到正文，不要求为了证明调用再次 cat 技能。

## Hook 与配置回读

最初三项新路径 Hook 因需要重新信任而被宿主拒绝，保留实际失败；不能将那时的技能成功说成工程核心已经送达。用户明确批准后，通过正式配置接口确认三项 trusted。调用前已是 trusted，这次 API 操作为幂等确认，不把此前的变化归因于该次写入。

再次启动新进程，SessionStart、UserPromptSubmit、SubagentStart 均实际 completed；无继承聊天历史的只读子执行者也完成了任务文档核对。测试结束后，精确移除宿主新增的两项临时项目信任；相对更新前最终只变化目标版本 ref 和三项获准 Hook 的内容信任摘要。

## 证据与局限

完整结果与冻结轨迹归 StoneDocs 的 [P003 验证记录](https://github.com/sty20030818/StoneDocs/blob/3d83a76cb3a27247e60b87357f05696327642ed0/docs/phases/p003-installed-workflow/verification.md)持有，任务状态不在此复制。归档含原始线程标识、提示、技能注入、相关命令、实际产物、Hook 事件和独立审阅；排除无关全局记忆输出与隐藏推理。

- 有限样例不证明长期自动选择稳定性、所有业务项目或桌面 UI 显示。
