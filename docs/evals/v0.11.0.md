# v0.11.0 版本验证

## 版本与受检范围

2026-11-25，个人升级的基线是 StonePlugins v0.10.0。新版本选入 StoneDocs CLI 0.3.0、十二份 v2 规则资源和独立固定的 Linear 指南。三项上游输入对应本地 Git 提交 `7b6e13860c4b90609ae0762c58bf034e0650c31e`。插件版本、CLI 版本、规则契约和采用项目身份分别由[插件清单](../../plugins/stoneplugins/.codex-plugin/plugin.json)、[产物清单](../../plugins/stoneplugins/tools/stonedocs/artifact.json)、[规则清单](../../plugins/stoneplugins/tools/stonedocs/rules/source.json)及各项目采用记录维护。Linear 指南的来源头见[固定入口](../../plugins/stoneplugins/references/linear.md)。

验收关注包内 `result show --view index` 能定位原生批次和手写小节、默认读取继续返回完整正文，以及 plan、task、review、verify、linear 对已接入且获授权项目的同轮同步与读回说明。个人安装应按实际本机来源、版本、插件内容与新进程发现判断；远端发布和实际 Linear 写入以相应系统中的证据为准。

StoneDocs 在上述提交运行 `npm run check`，289 项回归通过，文档检查覆盖 69 份 Markdown 和 895 个本地链接。使用该提交同时指定程序和规则版本，以 `build:cli --release` 生成 0.3.0。StonePlugins 通过正式导入命令读回 47 项声明文件，十二份资源与对应作者原文逐字一致。独立导入的 Linear 指南正文与同一提交的作者原文一致。

StonePlugins 的 `npm run check` 通过，57 项回归通过，生成的 Hook JS 与仓内原件相同。在插件目录中运行配套 CLI，P006 的索引返回 52 个标题位置，共 4,470 字节。P006 原本的七个手写批次仍可按行定位。此前受信任版本的 Hook 声明、运行脚本、源码、工程核心和三份细则共七个文件与新版逐字一致；新路径的宿主信任状态须以安装后读回为准。

## 本地快照安装与读回

以插件提交 `5d36eaf1e06cf398503933256a7a1ae57b887816` 为安装对象。首次通过原生 `plugin/install` 安装时，独立进程发现了新版，但个人市场仍登记 GitHub 的 `v0.10.0`；随后启动原生 Codex 终端，缓存实际回到了旧版。

最终把该提交的市场清单和插件目录导出到个人数据目录下以完整提交号命名的持久目录，用原生 `marketplace remove/add` 将 `stonefish` 切换到此目录，再运行 `codex plugin add stoneplugins@stonefish`。原生终端启动并完成审核后，新的 `codex plugin list -m stonefish --json` 返回 v0.11.0、已安装、已启用及同一固定本地来源。若要回到以前的 GitHub 渠道，可按安装说明重新登记可取回的固定 tag。

用户授权后，在原生界面对 SessionStart、UserPromptSubmit、SubagentStart 各自核对插件名与新版脚本路径，逐项信任。关闭审核界面后，新 app-server 读回三个 Hook 均为 enabled、trusted，11 个技能全部从 v0.11.0 加载，技能与 Hook 的加载错误数均为零。另外四个 Hook 的完整元数据摘要与升级前相同。StoneDocs 目录的信任弹窗出现在首次审核启动期间；用户另行确认保留现有目录信任，最终读回为 trusted。

已安装的 81 个文件及其可执行位与插件提交逐项相符。从最终安装目录运行 CLI，版本为 0.3.0。P006 索引为 4,470 字节，52 个标题行号逐项对应原文，包含七个手写批次；默认全文为 146,621 字节。受检插件提交通过 `npm run validate:release`。
