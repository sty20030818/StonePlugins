# v0.5.4 验证记录

日期：2026-10-14。基线为正式发布的 v0.5.3。本记录保存 v0.5.4 发布候选的复现与验证；正式发布状态以 [GitHub Release](https://github.com/sty20030818/StonePlugins/releases/tag/v0.5.4) 和 [tag 流水线](https://github.com/sty20030818/StonePlugins/actions/workflows/validate.yml)为准。

## 复现与原因

原始会话确认完整核心与每轮提醒已送达。回复实际写成 `**编辑路径。**点记录`，闭合后紧接正文；不是 Hook 插入了内部空格。Marked 在原回复中识别到 7 处未解析的加粗标记。最小样例同样无法解析为 strong；`**编辑路径** 点记录。` 则正常解析。

Hook 只输出上下文，不处理最终回复。v0.5.3 的格式约束位于公开决策说明中的方法标签段落，对普通设计建议的范围不够明确；每轮执行提醒未指向格式规则。模型生成了无效边界，不能把规则送达当成执行成功，也不能仅据此认定某个模型版本存在固定缺陷。

## 本轮修复

- 共享核心新增“回复格式”，覆盖工程任务的进展、结论、建议列表和公开决策说明；使用短标签、把句末标点放在外部、闭合后接正文时留 ASCII 空格，并在发送前检查。不确定时使用普通文本。
- 原方法标签段落引用该规则，不维护第二份格式要求。
- 每轮 Hook 提醒指向核心“回复格式”并要求检查全部加粗；255 UTF-8 bytes，仍在 300-byte 上限内。生命周期上下文为 6,884 bytes，仍在 8,000-byte 上限内。
- 不扩大工程流程到普通聊天；个人全局 AGENTS.md 保持不变。

## 检查与行为样本

`npm run check` 的 typecheck、build、仓库校验与 10 个 Hook 测试全部通过。逐轮提醒测试确认格式检查要求仍在短提醒中；生命周期、同包完整读取、损坏输入与防泄漏检查保留。

桌面运行时为 0.162.0-alpha.17.2，推理强度为 ultra。三个独立 CLI 进程均在原始日志中确认完整候选核心及逐轮格式提醒；没有改变全局默认模型。

| 样本 | 模型 | 输入 | 解析为 strong | 未解析标记 | 闭合后接正文缺空格 |
| --- | --- | --- | ---: | ---: | ---: |
| A | gpt-6-astra | 三个设计发现、四个建议，未要求加粗 | 4 | 0 | 0 |
| B | gpt-6.1-sol | 与 A 同题 | 0 | 0 | 0 |
| C | gpt-6.1-sol | 四条建议，要求开头加粗短标签，未教授空格写法 | 4 | 0 | 0 |

B 使用普通文本，不能独立证明加粗写法正确；C 验证了原问题模型在需要加粗时的输出。解析检查先用错误边界、正确写法与行内代码核对，避免把字面代码当失败。

## 本机试验与验收边界

试验期间，本机同一个 stonefish marketplace 临时指向本地仓库，防止固定 v0.5.3 来源覆盖候选。安装的 11 个文件与候选逐字节一致；其他配置和个人全局规则校验值未变。不使用临时来源覆盖的新 CLI 进程，也在原始日志中收到完整候选核心和逐轮格式提醒。该阶段版本字段仍为 0.5.3，实验正文与本版相同。正式安装须切回 Git 来源并固定 v0.5.4，回读版本化缓存与新进程日志确认送达。

只有三个行为样本，不能证明失败率改善或永久遵守。未验收 Codex 界面字体粗细；SubagentStart 只检查 Hook 输出与自动测试，本轮没有实际启动子 Agent。没有继承历史版本的 UI 或跨宿主通过结论。

发布检查沿用 `npm run check`、`npm run validate:release`、隔离副本复验及 tag CI。生成的 Hook 必须与 TypeScript 源码一致；本版不新增依赖，不修改个人全局规则。
