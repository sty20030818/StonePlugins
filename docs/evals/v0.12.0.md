# v0.12.0 版本验证

## 受检范围

本次调整 engineering 技能和每轮提醒。日常工程结果采用独立的 Markdown 三级标题和无序列表，存在有序流程时标明当前位置，有实际接续时单列「➡️ 下一步」并明确接手人。需用户作决定时单列引用块。评测使用 [TIMING-1](behavior-cases.md#timing-1-工程回复与接续)。配套 StoneDocs CLI 为 0.3.0，规则与 Linear 指南的固定来源见[v0.11.0 版本验证](v0.11.0.md#固定构建与包内检查)。

## 工作树检查

2026-11-27，在 StonePlugins 仓根分别向生成的 Hook 提交 SessionStart、SubagentStart 和 UserPromptSubmit。前两项各输出 7,324 个 UTF-8 字节，正文含三级结果标题和「➡️ 下一步」约定；每轮提醒为 297 个 UTF-8 字节。以上是工作树脚本的实际输出。个人安装后的观察重点是新对话能否给出真实标题、流程位置，以及有接续时由谁执行下一步。

## 正式发布与个人安装

2026-11-27，候选提交 `43b6b6a` 通过本地完整检查（57 项回归）和发布门禁。两份旧版评测的历史安装记录先独立提交为 `5637ca0`。[主分支 CI](https://github.com/sty20030818/StonePlugins/actions/runs/45855319577) 和[标签 CI](https://github.com/sty20030818/StonePlugins/actions/runs/45855505724) 在 Node 22.18.0 和 24 均通过，标签任务实际执行版本匹配和发布产物门禁。`v0.12.0` 指向该候选，上海时间 00:06 创建[正式 Release](https://github.com/sty20030818/StonePlugins/releases/tag/v0.12.0)，按标签与 Latest 独立读回同一正式记录。

发布后通过 Codex 原生市场从 GitHub v0.11.0 更新到 v0.12.0。81 个安装文件的内容与可执行位均与正式标签一致，配套 CLI 为 0.3.0。新版路径下三个工程 Hook 初次显示待审核；经用户授权，在原生界面逐项核对事件、插件和脚本后信任。关闭审核界面后，独立进程发现 11 个已启用的同版本技能和 3 个已启用且受信任的工程 Hook，加载错误和告警均为零。另外四个 Hook 的完整元数据摘要与安装前一致。

## 桌面新对话试读

个人安装和信任读回后，创建新的 Codex 桌面对话。会话记录可定位到安装版核心与每轮短提醒。按实际回复顺序观察：

- **首次发版交接** 提问要求只读核对版本并告诉接手人还剩什么。回答正确报告了当前版本和发版执行者的收尾动作，却用加粗文字作标题，未单列三级「➡️ 下一步」。本例格式未通过。
- **明确要求重写** 在同一对话点明工程小结格式后，结果与「➡️ 下一步」均成为三级标题，下一步写明由发版执行者补录评测并推送。
- **实际工程验收** 随后的请求要求直接从安装路径运行两个 Hook。回复的 Markdown 原文使用 `### ✅ StonePlugins 0.12.0 的两个安装版 Hook 均通过验收`，下面有三条无序要点，随后以 `### ➡️ 下一步` 单列接手人与动作。安装路径下 SessionStart 输出 7,351 个 UTF-8 字节，UserPromptSubmit 为 297 字节。

以上确认了一次真实新对话的输出与接续。后两轮共享首次回复和格式重写的上下文，首次默认命中仍有遗漏。本次读回的是实际消息的 Markdown；桌面原生界面限制自动读取，未据此判断字号、字重与间距。
