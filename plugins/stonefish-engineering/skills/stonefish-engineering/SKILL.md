# 石头鱼的工程规则

面向用户时称为“石头鱼的工程规则”。仅在显式调用、配置、日志或排障时使用 `$stonefish-engineering`，普通叙述不使用该标识。

目标是**最小完整方案**：修复根因，行为归正确所有者，保持单一事实源，不留无退出条件的旁路或永久双轨。“长期最优”只依据不变量、真实消费者、现有约束和明确方向，不设计猜测未来。

有新证据时重新评估并说明变化；否则可保留专业意见。合法且未越权的用户决策，按最终决定执行并说明保留意见。

## 常驻工程检查

每个工程任务都轻量检查：

- **所有权与事实源**：沿真实路径找共同所有者；同一业务知识只维护一份，不以 DRY 合并变化独立的相似代码。
- **职责与边界**：按变化原因落实单一职责、高内聚低耦合、信息隐藏与局部性，不按长度拆分。
- **简洁与长期性**：用 KISS、YAGNI 和最小公共面控制概念、依赖、冗余与兼容代码；不实现假想扩展。
- **修改范围**：外科手术式修改限定因果边界，Boy Scout Rule 只改善边界内的相关结构。
- **风险与证据**：正确性、数据、安全、权限、可访问性与用户约束优先；完成须有相称证据。

检查不等于制造结构；已满足时保持不变。整洁架构、六边形、DDD 和迁移模式只在信号真实出现时采用。

## 工作顺序

1. **理解真实路径**：读任务、指令、代码、调用方与消费者，定位不变量、状态、副作用、契约和失败边界；能查明的不反问。
2. **定义完成判据**：写清可观察结果及最小证据。
3. **按信号读取参考**：
   - 代码、配置、依赖或迁移：[references/change-boundaries.md](references/change-boundaries.md)。
   - 模块、数据、接口、依赖、兼容、权限或安全边界，以及跨模块/破坏性重构：[references/architecture.md](references/architecture.md)。
   - Bug、非平凡逻辑、测试、审查、安全、权限、金钱、持久化、迁移或外部副作用：[references/verification.md](references/verification.md)。
   - 多方法采用或比较、分类不确定、规则维护或固定评测：[references/methodology-index.md](references/methodology-index.md)；普通任务不为浏览名称而读。
4. **选择正确所有者**：在相关路径的共同位置修复，不在调用点重复补丁。
5. **实施最小完整改动**：完成必要连带调整，不扩散到无关清理。
6. **以证据收尾**：运行相称检查，审查最终 diff，区分已验证与未验证。

## 决策优先级

冲突优先级：正确性、数据、安全、权限、可访问性与用户约束；需求和公共契约；项目指令与硬约束；领域边界、局部性、单一事实源与长期成本；KISS、可读性与最小改动量。最小 diff 不胜过正确所有者，通用方法不胜过项目事实。

## 完成条件

- 可观察判据成立，没有已知相关路径仍依赖旧错误行为。
- 新增抽象、文件、依赖和兼容代码都有当前消费者与必要性；否则删除。
- 验证覆盖风险并说明未覆盖边界；行为变化同步权威文档，超出授权时列为待确认。

## 本次决策与方法论

仅当方法论、工程判断或用户约束实质改变所有者、范围、契约、风险、兼容或验证时，显示 `## 🧭 本次决策与方法论（石头鱼的工程规则）`；否则不显示。方案放在推荐后、确认前，交付放在结果与验证后。它是公开摘要，不是隐藏思维。

按**独立决策**组织，披露所有实际改变用户判断的方法，不设 `1～3` 项固定上限。每个方法或同作用、同分类的近义方法族单独一项：**{准确名称（分类）}**：{如何改变决定}。只读取、检查或事后贴名不算采用。分类限工程原则、架构方法、改造策略或验证方法；无准确名称时写“工程判断”或“用户明确约束”。

Markdown 自适应展开：

- **简单**：单行“决定 → **{方法族（分类）}**：{作用}；**预期影响**：{影响}”；已交付时换成“方案影响”。
- **普通**：用 `### {emoji} 决策 {n}：{具体决定}`，配“为什么适用”、逐项方法、阶段对应的影响与可选验证。
- **复杂/大量**：先用摘要或紧凑表格覆盖会改变用户判断的决定，只展开需确认、高风险或有真实竞争的项；其余随对应阶段交付，不重复。三个以上方法共享字段时才用 `方法论 | 分类 | 本次作用` 表格。

更高优先级的输出约束优先；压缩时不混淆决定，无法列全则说明省略边界。方案用“预期影响、验证计划”；交付用“方案影响”，验证决策另标“验证证据”。完整检查留在正常“验证”部分，不虚构代价、备选或证据。

Emoji 仅定位，每个决策最多一个：🧩 设计/职责、✂️ 简化、🛡️ 安全、🧪 验证、🔄 迁移；删除后文字仍须完整可懂。加粗标签的标点放在 `**` 外。
