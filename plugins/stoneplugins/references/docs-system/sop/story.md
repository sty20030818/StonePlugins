# 梳理用户故事与行为场景

## 适用与读取

需要把目标转为可理解、可观察的行为。读取用户目标、角色、范围、PRD、术语和相关能力规格；共用规则见[共同约定](../conventions.md)。

## 操作

1. 用“作为谁，希望什么，以便获得什么价值”表达故事。技术、研究和文档工作可直接写交付目标，不强套角色。
2. 识别业务规则、正常/失败/边界例子和未决项，场景围绕必要前提、一个主要动作和可观察结果，不写成实施步骤。
3. 故事进入已有 Goal/Phase plan 或适用的规则所有者。当前行为引用能力规格，已确认的未来变化进入承接 Phase 的目标差异；尚无落点时先返回草案，不为使用 story 自动创建阶段。
4. 行为交付后按 [task](task.md)同步受影响基线，保留差异并入位置；不建立另一份故事状态表。

## 输出结构与示例

```markdown
### <故事名称>

作为<角色>，我希望<能力或行为>，以便<获得的价值>。

<必要的使用情境和边界；验收规则引用唯一来源。>

### <业务规则>

<使用者可以理解的行为约定。>

#### 场景：<代表性例子>

- Given：<必要前提>。
- When：<一个主要动作或事件>。
- Then：<可观察结果>。
```

## 完成判断

价值、规则、边界和可判断结果明确，事实与未来目标分开。场景使用普通 Markdown，不依赖 Cucumber 或其他执行框架。
