# 形成实施设计

## 适用与读取

存在需要共同审查的结构、契约、关键流程或实施取舍。读取明确目标、相关 Phase plan（存在时）、行为标准、当前架构、决定及实际实现；共用规则见[共同约定](../conventions.md)。

## 操作

1. 确认设计要满足的成果与约束，先理解已有实现，沿用已确认架构。
2. 围绕共同审查的方案组织阶段 design.md；独立主题需要分开维护时用 designs/<topic>.md。多项 Task 可以共用一份设计，不按 Task 数量复制。
3. 按当前成果需要说明运行形态、目录与模块职责、输入输出和关键路径。新建或调整技术栈时，说明必要依赖、版本或发布通道、配置入口及选择理由；已有适用约定只引用，不为所有项目强制同一套架构。
4. 按实际影响展开数据所有权、权限边界、接口契约、事务与并发、失败处理、兼容、迁移及恢复；不涉及的内容无需为凑模板增设结构。
5. 解释选择与代价，重要长期取舍引用 decision，不维护第二份决定正文。涉及运行环境时，说明当前成果所需的最小可运行基线、环境前提和运行方式；按 [verify](verify.md)安排关键路径和失败路径的必要验证，不把计划写成实际成功。
6. 仅讨论或尚无阶段时先返回草案，不为使用 design 自动创建阶段或任务。未来方案保留在草案或阶段资料，不影响当前成果的未来细节不阻断本次设计；实际交付才同步受影响的当前规格/架构。

## 输出结构与示例

```markdown
# <方案主题> 实施设计

## 目标与约束
<目标和计划来源、已有架构/契约及本次范围。>

## 实施方案
<当前成果所需运行形态、目录与模块分工、输入输出和关键路径；按影响展开数据、权限、接口、事务并发、失败和兼容。>

## 选择与理由
<采用方案、必要依赖及版本/通道选择、真正影响选择的替代项、代价与确认依据；引用重要决定。>

## 影响与恢复
<受影响使用者、文件或数据；有迁移或覆盖时说明精确范围、恢复方式和限制。>

## 验证安排
<标准来源、关键风险、验证对象和方法；涉及运行环境时补可运行基线及必要前提，不预填实际成功。>

## 待决事项
<仍影响实施的选择或风险；无则删去。>
```

## 完成判断

当前待实施成果的关键选择明确，后续执行无需重新决定这些选择，影响当前成果的未决风险有去向。设计交付不等于实现完成，需要执行时按 [task](task.md)接续。
