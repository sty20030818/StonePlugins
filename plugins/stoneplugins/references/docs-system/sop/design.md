# 形成实施设计

## 适用与依据

存在需要共同审查的结构、契约、关键流程或实施取舍。 共同权限、状态与版本规则见[共同约定](../conventions.md)。

## 读取

已明确的目标与约束、相关阶段计划（存在时）、行为标准、当前架构、已有决定和实际实现。

## 操作

1. 确认设计要满足的成果与约束，先读已有实现和契约，沿用已确认架构。
2. 围绕需要一起审查的方案组织 design.md，存在独立主题时使用 designs/<topic>.md；多项任务可引用同一设计。尚无阶段或只讨论方案时先返回独立草案，有项目既定且已授权的设计落点时写回该处；不为使用 design 自动创建阶段和任务。
3. 说明模块职责、输入输出和执行路径，按真实影响展开接口、数据、权限、失败、兼容、迁移或恢复，避免为凑模板增设结构。
4. 说明选择依据与影响，持久的重要取舍引用其 decision，不另维护一份决定正文。
5. 安排与风险相称的验证方法；未来方案保留在对应设计草案或阶段资料中，实际交付时才更新当前架构和规格。

## 产出与完成

完成意味着后续执行无需重新决定关键实施选择，未决风险有明确处理方式。后续需要拆分或执行任务时按 [task SOP](task.md) 承接。

## 输出结构与示例

本节提供 design.md 的填写骨架；按本次实际影响保留相关小节。

```markdown
# <设计主题或阶段标识> 实施设计

## 目标与约束

<引用已明确的目标与范围来源；已有 plan 时引用它。列出设计必须遵守的已有约束。>

## 实施方案

<模块或文档如何分工，输入输出与主要执行路径，哪些现有内容需要调整。
按实际需要说明接口、数据、权限、兼容性或协作边界。>

## 选择与理由

<采用的方案、影响选择的替代项、取舍及确认依据。
已有重要决定引用 decisions 中的记录，不维护第二份决定正文。>

## 影响与恢复

<受影响的使用者、文件或数据；有迁移或覆盖时说明精确范围、恢复办法与限制。
没有相关影响时可说明原因并保持简短。>

## 验证安排

<引用标准来源，说明用什么方法验证关键风险、需要什么环境或前置条件。
实际执行结果进入 verification，不提前填写成功。>

## 待决事项

<尚未解决且影响实施的决定或风险；无则删去本节。>
```
