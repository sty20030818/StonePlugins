# 验收与复验交付

## 适用与依据

已有明确交付对象，需要实际验证、复验或检查证据是否充分。 共同权限、状态与版本规则见[共同约定](../conventions.md)。

## 读取

完成条件、适用标准及阶段差异、受检对象、已有验证记录和实际授权。

## 操作

1. 明确要回答的问题与必须覆盖的条件，标准不足时说明缺口，不能自行降低或改写标准来取得通过。
2. 固定实际对象和标准版本。优先引用完整可取回的提交或构建；HEAD 不代表未提交改动或未跟踪文件。没有完整可取回版本时，仅保存受检范围的只读原文快照、文件清单和哈希，独立读回校验，避免复制无关资料或凭据。哈希不代替原文。
3. 执行与风险相称且在授权内的检查。已有有效证据可以复用，只补缺失或失效部分，必要检查通过后不无故重复扩大。
4. 按本页输出结构追加验收批次，记录实际执行与逐条件观察；命令检查包含退出码。分别描述静态、实际行为和外部运行；未执行、失败、未知不可混同。
5. 复验追加批次保留旧失败；标准改变注明版本和依据。证据错误追加更正说明，修复需求交回所属任务，不悄悄扩大实现范围。
6. 读回结果、快照与链接，确认文件实际存在、内容非占位、对象和标准匹配。未来才生成的报告不能作为证据。

## 产出与完成

实际结果进入 verification，不建立第二份活跃标准。验证结束不等于实现完成；验证或审阅自身若有任务，由当前执行者按它的原定完成条件写回，无需循环启动 task。

## 输出结构与示例

本节提供一个交付目标的验收记录结构。后续批次在同一目标记录中追加；版本固定和复验判断按上方操作执行。

```markdown
# <交付目标>验收记录

## 交付目标与范围

<这组验收要回答什么，关联哪个阶段成果或任务。
链接标准来源，并说明此次覆盖与排除的范围。>

## 批次 <日期与本文件内唯一序号>

### 对象与标准版本

- 对象：<受检代码、文档、产物或服务>。
- 对象版本：<可核对的提交、构建、快照，或未提交文件的可恢复快照、清单与哈希>。
- 标准来源与版本：<规格或阶段条件的位置，以及本批使用的具体版本标识>。

### 方法与环境

- 方法：<实际采用的检查、操作步骤或测试方法>。
- 环境：<对结论有影响的平台、配置、工具版本和前置条件>。
- 执行信息：<实际日期、执行者或执行方式>。

### 结果与证据

#### <被核对的条件或场景链接>

- 实际观察：<发生了什么，实际输出或行为是什么>。
- 结果：<通过、失败或未验证；不适用须说明依据>。
- 证据：<日志、产物、截图、检查输出或可复核的记录位置>。

### 限制与后续

<未覆盖或无法确认的内容，以及结论适用范围。
发现需要处理的问题时链接所属任务；复验在后续批次记录。>
```
