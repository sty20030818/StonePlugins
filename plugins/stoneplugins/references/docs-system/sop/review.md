# 审阅阶段与收尾

## 适用与依据

需要评估阶段成果、记录复盘，或按授权完成收尾与原地归档。 共同权限、状态与版本规则见[共同约定](../conventions.md)。

## 读取

阶段 plan/tasks、适用验收记录、当前规格/架构、遗留接收依据及本次授权。

## 操作

1. 区分只读判断、记录复盘和实际归档；“能否结束”的询问不自动授权归档。
2. 逐项核对原定成果与退出条件、对象和标准版本、适用证据。任务数量、提交或发布不能替代成果判断；缺失或失效部分交给 [verify](verify.md)，不改条件制造成功。
3. 检查当前基线同步及遗留去向。非阻断事项可按 [task](task.md) 明确交接后收尾；影响原退出条件的事项必须完成，或先确认范围调整，不能靠移走或改叫优化规避。
4. 先把有依据的判断、遗留处置和必要经验写入 plan 收尾节；具有独立复盘价值再使用 review.md。随后读回。
5. 有独立审阅任务时，按它的完成条件记录结果。“形成判断”可完成审阅工作，即使结论是暂不能收尾。既有任务与归档互设前置时先明确解决冲突，不能临时填 done 绕过。
6. 满足条件且已获授权后写阶段 done 和 archived；取消按明确决定写 cancelled、原因和遗留处置。保留原路径与证据，roadmap 调整为历史入口。
7. 后置读回实际状态和入口，偏差直接记录修正，不因此再次启动完整 review，也不保留不成立的完成结论。

## 产出与完成

完成意味着阶段判断有依据、遗留有处置，实际状态与本次授权相符。归档不自动提交或发布；发布关系和记录遵守[共同约定](../conventions.md)。

## 输出结构与示例

本节提供具有独立复盘价值时的 review.md 结构；简短判断可以使用相同信息组织在 plan 的收尾节。

```markdown
# <阶段标识> 阶段复盘

## 审查范围

- 审查日期：<实际日期>。
- 对象与依据：<阶段计划版本、交付物版本及验收记录链接>。

## 成果与退出条件

### <plan 中的某项退出条件链接>

- 判断：<成立、不成立或仍无法确认>。
- 依据：<验收批次、实际产物与必要解释>。

<逐项核对原定条件；发生过范围或标准调整时引用决定与理由。>

## 偏差与质量发现

<实际成果与计划的差异、失败与修复、仍存在的限制，以及值得保留的方法。
根据实际问题判断是否需要重构或优化。>

## 遗留与交接

<每项遗留的影响、是否阻断退出、任务标识和明确接收位置。
这里只保存本次处置快照，后续状态沿链接查看。没有遗留时如实说明。>

## 当前基线同步

<已进入长期规格、架构或指南的内容及位置；确认阶段差异已转为历史引用。
尚未交付内容的去向及原因。>

## 收尾结论与下一步

<本次是否具备完成、取消或归档条件，判断依据及仍需处理的事项。
后续建议和已批准工作分开记录；阶段状态按 SOP 写回 plan。>
```
