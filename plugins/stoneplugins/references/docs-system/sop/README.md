# 标准操作流程

按当前问题选流程，不要求逐项顺序调用。共同规则见[文档约定](../conventions.md)，各流程的产出要求由对应 SOP 维护；需要填写骨架的流程另设“输出结构与示例”。每份 SOP 拥有自己的输入、操作、输出结构和完成判断；本目录只导航。

| 当前要做的事 | 流程 | 主要产出 |
| --- | --- | --- |
| 记录或处理一个想法 | [idea](idea.md) | 想法待办或已明确的去向 |
| 调查并比较可行方案 | [compare](compare.md) | 有依据的研究与推荐 |
| 追问取舍并形成决定 | [decide](decide.md) | 写回原所有者的决定，必要时 decision |
| 梳理价值与行为场景 | [story](story.md) | 故事、规则与验收示例 |
| 规划成果阶段 | [plan](plan.md) | 阶段计划与 roadmap 关系 |
| 形成需要审查的实现方案 | [design](design.md) | 实施设计与验证安排 |
| 拆分、执行或交接任务 | [task](task.md) | 实际交付、任务记录与接续点 |
| 验收或复验交付 | [verify](verify.md) | 版本化的实际结果与证据 |
| 判断成果并按授权收尾 | [review](review.md) | 阶段结论、遗留处置与归档 |

想法和研究不自动成为执行承诺；已经明确的任务可以直接进入 task，执行与 verify 可以在同一会话连续完成。阶段结论由 review 判断。具体权限和判断步骤由相应 SOP 维护。

这些流程不要求安装同名技能。人或 AI 均可按文档执行，已有工具和技能按采用项目的实际环境使用。技能通过文档交接，不以循环回调来更新状态。

独立入口与资料不足的处理见[共同约定](../conventions.md#流程独立与组合)。采用项目可在自己的使用指南中说明常见组合及返工/恢复路线；本目录和各 SOP 不依赖该指南文件。
