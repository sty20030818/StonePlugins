# 规划产品目标或成果阶段

## 适用与读取

规划或调整一个 Goal 或 Phase。先明确本次对象，读取项目入口、PRD、roadmap、已有目标/阶段、相关标准和决定；共用模型见[共同约定](../conventions.md)。

## 操作

1. 查找已有承接位置，优先接续同一成果，避免重复计划。Goal 定义整体目标和组成阶段，Phase 定义自己贡献的成果及退出条件。
2. 按下方对应骨架记录已确认范围、条件、依赖和风险；输入可以直接来自用户目标，不要求先调用 story。需要补行为场景时按 [story](story.md)处理。
3. Goal 的整体条件引用阶段与能力标准，只补组合后的用户结果。Phase 的新增行为写目标差异；没有变化不复制当前规格。
4. Goal/Phase 可以先粗排，Phase plan 包含必要技术概述；新项目或整体重审按 [design](design.md)讨论总体方案，细拆受影响实施任务前核对适用设计、关键选择和验证依据，读取[技术设计方法](../knowledge/technical-design.md)的任务就绪章节。已有适用方案直接引用，相关未知只暂停依赖它的实施安排，允许先调查，不用无关未来平台或普通可逆细节阻断当前工作。阶段写回时保留唯一 tasks.md 入口，未拆分时明确说明，不虚构 Task；Goal 不设任务清单。
5. 范围变化先处理条件、依赖与确认依据，再按 [task](task.md)拆分。只规划不自动开始实现、发布或后续流程。
6. Goal 组成变更只写目标 plan；roadmap 仅更新受影响的跨目标关系和导航。发布意图按共同约定选择一个 plan 维护。
7. plan 记录所规划对象的成果、范围和条件。本轮编辑授权、操作经过及规划任务的完成记录留在执行 Task、验收或回复，不写成 Goal/Phase 的范围、退出条件或收尾结论。

## 输出结构与示例

### Goal plan

写入 `docs/goals/<goal>/plan.md`：

```markdown
---
id: V1
status: todo
---

# <产品目标>

## 背景、成果与范围
<关联 PRD、用户结果、确认依据，以及本目标包含/不包含什么。>

## 组成阶段
| Phase | 对整体目标的贡献 | 依赖 |
| --- | --- | --- |
| <阶段计划链接> | <需要取得的成果> | <具体前置成果或无> |

<这里只维护组成与关系，不复制阶段状态。尚未建资料的阶段明确标为规划项。>

## 整体验收条件
1. <组合成果应满足的用户结果、集成条件与适用范围>。
2. <引用阶段和能力标准，只补整体层面的判断>。

## 推进与风险
<阶段先后、可并行范围、关键外部条件及待决范围。>

## 材料与发布意图
<已有整体 verification 的入口；确有发布意图时简记选入成果和放行条件。
未创建的材料不预放无效链接，没有发布意图则删去相应内容。>

## 收尾
<按 review 记录整体条件判断、适用验收批次和遗留去向；有独立 review 则只链接。>
```

### Phase plan

写入所属目标的 `phases/<id>-<outcome>/plan.md`：

```markdown
---
id: P001
status: todo
---

# <阶段成果>

## 背景与目标
<引用所属 Goal，说明本阶段贡献、已有事实和确认依据。>

## 成果与用户故事
<可观察交付目标；需要时按 story SOP 补故事和场景，标准引用唯一来源。>

## 范围
- 包含：<本阶段承诺覆盖的能力与边界>。
- 不包含：<容易混入的额外工作>。

## 验收与退出条件
1. <独立可判断的阶段成果及必要验证>。
2. <适用标准及范围，不依赖 Goal 已 done 或已归档>。

## 推进、依赖与技术概述
<成果先后、具体依赖、必要技术思路、风险和未决选择。
详细设计按需链接，实际任务和状态见 tasks.md。>

## 目标差异
<按需保留：当前基线、拟增改删的行为、确认依据、场景；交付后注明并入位置。
未变化的规则只引用。>

## 阶段材料
- [任务清单](tasks.md)
- <实际存在的 design、spec-deltas、verification 或 review 入口；按需补充。>

## 发布意图
<确有本阶段独有的发布意图时保留；所属 Goal 已拥有同一意图时只引用。>

## 收尾
<按 review 补阶段条件判断、实际结果、基线同步和遗留去向；独立 review 只链接。>
```

### 发布意图

只选择一个承接 Goal/Phase plan，按显式版本简记选入成果引用与放行条件；没有意图不预建空块，一个承接对象可拥有多版，同版不在其它计划复制。条件复用已有有效标准与验收安排，仅补本版本组合所需判断，不复制任务状态。

使用 CLI 时先查看对应 help，原生块在上方发布意图章节内维护，已有正文保留；归档计划不追加普通意图，已完成但未归档的成果仍可安排发布。实际日期、产物、适用证据和限制由[实际发布记录](../conventions.md#目标与发布)拥有，不回写成计划状态；计划形成不意味着已经发布，实际记录也不要求补演本流程。

## 完成判断

对象明确，成果、范围、条件和关键依赖足以支持后续工作，未决项没有伪装成确认。计划形成不代表成果、版本发布或验收已经发生。
