# 记录与处理想法

## 适用与读取

有问题、灵感或改进设想，尚未形成实施承诺。读取产品目标、已有想法及相关任务；共用规则见[共同约定](../conventions.md)。

## 操作

1. 查找同一问题的已有记录或任务，已有承接位置就关联，不生成第二份待办。
2. 记录问题、期待价值和必要背景，分清事实、假设与待讨论项。
3. 存在真实方向选择时按 [compare](compare.md)调查，需要确认取舍时按 [decide](decide.md)处理；仅记录想法时到此结束。
4. 采纳、放弃或实现后移出待处理区，必要理由写回决定或研究；采纳实施时链接接收的 Goal、Phase 或 Task，不直接生成阶段外 Task。

## 输出结构与示例

写入项目的 ideas 待处理区，一条想法可使用：

```markdown
## <想解决的问题>

- 价值：<希望改善什么>。
- 背景：<已知事实与必要来源>。
- 待讨论：<假设、选择或尚缺的信息>。
```

## 完成判断

内容可理解、无重复承诺；处理过的想法有明确去向。记录完成不等于批准实施。
