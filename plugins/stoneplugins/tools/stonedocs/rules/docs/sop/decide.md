# 形成并记录决定

## 适用与读取

需要澄清目标、追问取舍或将讨论结果转为有效决定。读取已确认目标、相关比较、约束及受影响资料；权限见[共同约定](../conventions.md)。

## 操作

1. 分清已确认选择与真正未决问题，先调查项目内可以发现的事实。
2. 针对会改变方向的分歧追问，给出推荐和适用边界，按项目约定确认关键影响。
3. 明确实际批准的范围；方向确认不代表未讨论细节、额外任务或发布也获批准。
4. 决定写回对应内容所有者。仅当取舍重要且长期需要解释时，另建 decision，并从使用处引用，不重复维护决定正文。
5. 未决项留在所属计划或研究，执行工作再按 [plan](plan.md)、[design](design.md)或 [task](task.md)承接。

## 输出结构与示例

普通确认直接写回所属资料；独立 decision 按需使用：

```markdown
# <稳定标识> · <选择主题>

- 日期：<实际确认日期>。
- 情况：<accepted；被后续决定替代时标明 superseded 及链接>。

## 背景与选项
<问题、约束、真实选项及必要比较来源。>

## 决定与理由
<已确认选择、适用范围和确认依据。>

## 影响与代价
<需要接受的限制、受影响所有者及替代关系。>
```

## 完成判断

决定、依据、影响及未决范围可找到，确认内容与实际授权一致；未决草案不标成 accepted。
