# Design

为新项目、整体技术重审或明确交付目标形成总体或阶段技术方案。按[规则与方法读取](../../references/cli.md#规则与方法读取)先定位项目本地适用规范；包内[共同约定](../../tools/stonedocs/rules/docs/conventions.md)与[技术与实施设计 SOP](../../tools/stonedocs/rules/docs/sop/design.md)供未采用讨论或显式版本核对；输入、操作、写回与完成判断由这些文档维护。填写结构见[设计输出结构与示例](../../tools/stonedocs/rules/docs/sop/design.md#输出结构与示例)，资源版本见[固定快照清单](../../tools/stonedocs/rules/source.json)。

## 项目读取

沿项目入口读取明确的目标与约束、适用行为规则、当前架构、重要决定和实际实现；已有 Goal、所属 Phase 计划或未来行为差异时一并读取。可直接从充分的用户材料或项目事实进入，不要求 plan、story 或其他技能先运行。按项目采用的规则版本和明确差异解释材料，版本未知或契约冲突按共同约定处理。

项目适用 v2 时，按上述读取路线取得项目实际的[技术设计方法](../../tools/stonedocs/rules/docs/knowledge/technical-design.md#自适应文档组织)，围绕组织方式、初始设计、总体方案或已有项目迁移读取相关章节；包内链接是定位参照，不覆盖本地版本。旧 v1、作者模式和未采用讨论分别按共同适配说明处理。

## 执行适配

按技术与实施设计 SOP 使用项目已有工具核对实现并组织需要共同审查的方案。目标或约束不足时只澄清影响设计的缺口，已确认且仍适用的选择继续沿用；设计草案、获准写回与实现执行按本次授权区分。下游任务可直接引用设计，不依赖额外技能调用。

需要定位承接 Goal/Phase/Task 或读取项目 SOP 时，按[配套 CLI 用法](../../references/cli.md)使用只读入口；方案正文仍由当前执行者按本 SOP 编写和审查，CLI 不替代技术判断。

## 输出

说明完成的是总体或阶段设计、哪些实施输入已具备及哪些任务尚未细拆，再说明方案、关键选择及依据、影响与恢复、验证安排和未决问题，给出实际设计入口或讨论草案；未来方案与当前交付基线分别说明。
