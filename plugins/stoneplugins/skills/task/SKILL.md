# Task

从项目入口识别实际任务与本次授权。读取[共用 SOP](../../references/docs-system/sop.md)第 3、4、6 节，移交时再读第 7 节，创建记录时参考[模板](../../references/docs-system/templates.md)。资源来源见[固定快照清单](../../references/docs-system/source.json)，工作树来源只代表本地候选。

先区分讨论/只读审查与执行写回，按项目采用的 SOP 版本及明确差异解释资料。遇到影响本次读写的契约冲突，按 SOP 处理，不能用插件升级隐式改变项目规范。

## 读取与写入

读取所属阶段 plan、tasks，以及任务关联的 design、行为标准、决定和已有证据。路径由项目入口和关联资料提供，不要求项目迁移到固定目录。

在授权范围内更新实际交付文件、受影响的权威文档，以及所属 tasks 中的任务记录。只讨论时提供草案，不创建或更新任务文件。

## 推进工作

1. 根据任务 ID 或成果定位唯一工作记录，明确完成条件、依赖、当前事实和允许范围。已移交则沿指针找到接收位置。已完成、取消或归档则区分历史查询、更正与新增工作，不直接重开。
2. 拆分任务时按可验收成果组织，采用项目稳定 ID。优先接续已有阶段，不自行创建另一份总任务表。涉及阶段目标或关键方案改变时，明确影响和所需确认。
3. 开工按 SOP 写回实际状态，执行中记录重要结果、阻塞和接续点。实现遵循已生效的项目工程约束，不把本技能当作替代工程规则的另一套规范。
4. 将实现与必要的规格、架构、指南更新形成同组可审查交付。尚未交付的目标差异继续留在阶段，不能仅补文字便宣布能力已经实现。
5. 按 [verify 流程](../verify/SKILL.md)取得与本次对象匹配的证据。已有证据充分且没有相关变化时复用，缺失的部分才补查。可以在同一会话连续执行，不要求另开 Agent。
6. 先写入并读回真实结果和证据。原定完成条件满足、必需验证有依据、权威资料同步后，才写 done。失败、未知、未验证按实际事实保留，记录缺口和可继续的下一步。
7. 交接时保留任务身份、完成条件和既有证据，原位置仅留去向指针。写前读最新内容，避免覆盖其他任务或协作者修改。

## 结果

给出本次任务、实际产物、证据入口、当前状态及必要接续信息。遵守 SOP 的状态和权限约定，任务完成不自动触发阶段归档或发布。
