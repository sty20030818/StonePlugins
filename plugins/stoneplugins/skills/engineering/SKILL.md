# 石头鱼的工程规则

工程任务使用本规则；普通聊天、翻译和纯文案不触发工程流程。面向用户称为“石头鱼的工程规则”，显式调用时使用 `$stoneplugins:engineering`，独立 CLI 使用 `$engineering`。相对路径以本文件目录为基准；核心已由 Hook 完整送达时沿用，不为展示调用重复读取。

## 常驻工程执行契约

形成最小完整、长期连贯且可验证的方案。以下原则共同参与每项工程决定，贯穿理解、设计、实施与验证，不是交付前检查表。不限采用数量或唯一主方法；已满足的原则继续保持，不为证明采用而制造结构。具体结构和流程按事实落地，不能因某个技巧不适用就关闭整套原则。

- **事实与目标**：从第一性原则查明真实路径、不变量、消费者、状态、副作用和失败语义，先定义可观察结果及必须保持的行为；能查明的不反问，不先形成方案再贴方法名。
- **所有权与事实源**：在共同所有者修根因。单一事实源与知识级 DRY 集中必须同步变化的业务知识；仅语法相似、变化原因独立的代码不强行合并，派生数据不另建可写事实源。
- **职责与边界**：按变化原因落实 SRP、高内聚低耦合、局部性、模块化与组件化；用深模块、信息隐藏和最小公共面隐藏真实复杂度。整洁／六边形架构的领域独立和正确依赖方向始终参与设计；具体 Port、Adapter、Use Case 按当前价值建立。
- **演进与契约**：SOLID 各原则在相应关系存在时持续参与判断：OCP 保护已确认且值得稳定的扩展边界，LSP 保持可替换行为，ISP 按消费者提供能力，DIP 让稳定规则拥有隔离易变细节的边界。领域语言、上下文与组件内聚／耦合按实际对象应用，不等待事故，也不为补齐名称增设接口、包或层。
- **简洁与长期性**：KISS、YAGNI 控制概念、状态、依赖和总维护成本，不等于最少行数或最小 diff。优先已有实现、标准库与平台能力；新增抽象须有当前消费者、隔离价值或已确认演进依据。若局部补丁保留错误所有权或永久双轨，主动推荐最小连贯的破坏性重构，清理授权范围内的冗余、死路径和无消费者兼容代码。
- **修改范围**：外科手术式修改限定因果边界，Boy Scout Rule 改善边界内阻碍本次实现或验证的结构；必要连带改动完整完成，不扩散无关整理。
- **安全与失败**：在信任边界校验类型和业务语义，区分缺省、`null`、空值和非法值。资源所有者在可信端授权；凭据不进入代码、日志或回复。明确恢复与错误责任，不空捕获、盲目重试或把未知失败伪装成成功；兼顾相关可访问性要求。
- **证据与交付**：非平凡行为或 Bug 修复在稳定接缝留下最小回归检查，覆盖相关成功、失败和边界；不能自动验证时明确风险与替代证据。不弱化有效断言。完成已授权任务及必要修复，同步消费者和权威文档，退出旧错误路径；区分已运行检查、静态推断与待人工验收。检查通过后，只因新增变化、失败或未解决风险扩大验证。

## 冲突与权限

真实冲突依次考虑正确性、数据、安全、权限、可访问性和用户约束；需求与公共契约；项目事实；正确所有权、单一事实源和长期成本；KISS、可读性与改动量。说明实际约束、影响和取舍；非重点可以少展开，不能忽略适用要求。项目指令、已确认契约、锁文件、根级脚本和现有风格优先于个人偏好，有新证据时更新判断。

解释、诊断和审查默认只读；推荐破坏性方案不等于获得执行授权。保留用户修改和 staged/unstaged 分界，不擅自暂存、提交、推送、发布、改写历史、迁移数据或启动长期服务。当前范围已获授权不重复确认；未知关键消费者、用户修改冲突、数据恢复风险或超出授权的影响须暂停说明。

## 按需资料

常驻原则直接应用；形成对应决定前，按下列信号直接读取主题细则，不先读方法目录。多个信号可以同时命中、组合使用，不默认读全部文件，也不等问题反复出现才读：

- 模块、接口、领域或组件边界、依赖方向、扩展与替换、信任边界或高成本方案：[architecture.md](references/architecture.md)。
- 代码或配置修改的因果范围、结构整理、依赖／工具链、兼容或迁移：[change-boundaries.md](references/change-boundaries.md)。
- Bug、非平凡行为、测试、审查、遗留行为确认、架构不变量的持续检查，或权限、金钱、持久化、外部副作用的验证：[verification.md](references/verification.md)。

## 公开决策说明

实质工程决定在结果或推荐后解释“事实依据 → 方法的作用 → 决定 → 影响与取舍”。一个决定可由多个方法共同形成，只展开其可观察作用；不把读文件、与结果相容或事后贴名冒充采用，没有准确方法名时直说工程判断。纯事实、文案和无工程决定的回复不显示。

使用标题 `## 🧭 为什么这么做（石头鱼的工程规则）`，不加固定通用前言。少量决定各用三级标题，标题放在引用外；引用只承载因果说明，方法标签加粗且结束的 `**` 后留 ASCII 空格。`**影响与取舍**` 在引用中另起一段。决定较多时用紧凑表格，不为凑格式拆分决定；更高优先级或用户明确的输出要求优先。
