# 修改范围与迁移

用于代码或配置修改的因果范围、结构整理、依赖／工具链、兼容或迁移。常驻原则共同形成决定；本文件补充具体改造策略，不要求每次修改都做迁移。

## 因果范围

外科手术式修改限定因果边界，Boy Scout Rule 改善边界内质量。从目标沿调用链、共享知识、状态与副作用找到必须共同改变的所有者；边界不是本次打开的文件清单。

- 完整修复同类消费者，共同业务知识归一个所有者；若局部补丁保留错误所有权、第二事实源、重复分支或已知返工，主动提出最小连贯重构。
- 清理本次产生的孤儿、死分支、未使用依赖，以及已证明在授权范围内且无消费者的旧路径；改善妨碍本次正确实现或验证的结构。
- 无关格式化、命名整理和历史问题不混入任务。只报告，不擅自写入债务清单或 issue；获授权后才扩大范围。

## Tidy First：区分结构与行为

小型、可回退的结构整理能明确降低本次行为修改风险或扩散范围时，默认先整理；否则直接完成行为目标。整理前后验证行为保持，再用目标证据验证行为变化，让两者可分别审查。

不强制拆独立提交，更不为整理改变用户暂存状态。拆服务、数据迁移或公共契约变更不是小型整理，仍须满足对应授权与恢复边界；Tidy First 只决定已授权因果范围内的先后顺序。

## 迁移选择

| 已确认约束 | 改造策略与退出条件 |
| --- | --- |
| 消费者可同步更新，没有外部兼容要求 | **Clean cut**：同批迁移调用方、测试、配置和文档，删除旧实现、失效形状测试、旧依赖与零消费者兼容壳；有效行为测试迁至新边界。 |
| 公共 API 或 schema 消费者不能同步升级 | **Parallel Change**：扩展 → 迁移 → 收缩；兼容放在边界，内部保持单一权威模型，明确迁移所有者、完成证据和删除时点。 |
| 替换内部库、框架或 provider，主干仍须持续交付 | **Branch by Abstraction**：在真实接缝逐步切换实现、验证等价与恢复；迁移完成重新证明抽象的长期价值，否则删除，不留下默认永久双轨。 |
| 大型遗留系统能按业务能力逐片替换 | **Strangler Fig**：通过真实路由／拦截边界转移能力；明确新旧状态所有者、双写或同步的一致性、失败恢复与收敛证据，再退出旧路由和旧系统。无安全接缝或状态无法收敛时先解决该约束。 |
| 大型源码重构不断暴露未知前置依赖 | **Mikado Method**：结合阅读和小型可恢复实验发现前置条件，记录依赖并按依赖顺序完成；不凭空规划整个依赖图，不无限探索。 |

Mikado 中需要撤销的实验优先在隔离副本进行，保留发现的依赖和验证证据，再实施可保留的步骤。不得用用户工作树或暂存区试错，不依赖破坏性 reset。小型重构的依赖和恢复路径已明确时直接实施，不强制创建依赖图。

迁移策略可以组合，例如用 Parallel Change 协调外部消费者，用 Branch by Abstraction 替换内部实现；每种策略只承担真实约束，不能因采用渐进迁移而放弃最终单轨。能干净切换时不增加渐进机制。

- 输入兼容须规定新旧字段并存、冲突、非法值和缺失值的语义，不把必填悄悄改成可选。
- 兼容退出依赖消费者证据、必要通知和恢复能力；观察窗口覆盖实际调用周期，不臆造期限或承诺日期。
- 破坏性重构先核对调用方、公共契约、存量数据、配置、自动化和部署约束，说明保持／改变的行为与切换顺序。数据迁移须明确所有者、停机影响及备份恢复；回滚代码不等于恢复数据。已授权范围不重复确认，未知关键消费者或超出授权的数据风险须暂停说明。
- 完成后搜索旧符号、配置、示例和文档。搜索无结果只证明静态遗漏检查，不替代运行时行为验证。

## 依赖与工具链

- 按现有实现 → 标准库／平台原生能力 → 已安装依赖 → 最小自有实现 → 新依赖查找合适能力，按正确性、项目适配与总维护成本选择，不为复用而复用。
- 沿用项目工具链、锁文件与根级脚本，不臆造命令、不擅自迁移包管理器或新增测试框架。新增依赖说明必要性、替代方案、成熟度、维护、安全、体积、升级及退出成本；许可证与分发成本在影响当前选择时展开。
- 依赖变更同步清单与锁文件，不制造无关锁文件变化。锁定版本问题查对应版本的一手文档，选型／升级再查当前资料；命名、格式与注释沿用项目惯例。
- 行为变化同步现有 README、接口说明、SOP、示例或架构决策的权威来源；不复制第二份契约。所有权不明或更新超出授权时说明缺口。

## 用户状态与提交边界

- 修改前检查工作树，区分已有改动与本轮改动；不覆盖或格式化无关修改，无法安全绕开时暂停说明。
- 保留用户已有 staged/unstaged 分界。已暂存的预期外依赖升级按用户已确认处理，不回滚、不拆分、不归为本轮 Agent 修改；需要继续改同一文件时留下未暂存差异。
- 用户明确要求提交当前结果时，按其约定处理既有已确认暂存内容与本轮已审核修改，不带入其他既有未暂存修改。依赖升级无需单独提交，除非用户另有说明。
- 未经授权不暂存、取消暂存、stash、还原、提交、推送、发布或改写历史；暂存区意外变化时暂停并报告，不自行恢复。删除或覆盖物质性内容前核对精确目标、影响、恢复方式和授权。
